queue_e11.sh `have` guard is keyed on the EAGER directory for E11d and E11e:

    have "results/${DATE}_E11d_${M}_eager_prefixsweep" || run "$M E11d prefix sweep" ...

but the command it guards writes BOTH modes. A run whose eager half succeeded and
whose reduce-overhead half crashed therefore looks complete, and re-running the queue
skips exactly the point that is missing. This is how smolvla E11d's compiled half would
have been lost silently; it was caught only because EXIT=1 was visible in the log.

Fix once NOTHING is executing queue_e11.sh (editing a running bash script is what
destroyed preflight pass 7): guard on both directories, e.g.

    { have ..._eager_prefixsweep && have ..._reduce-overhead_prefixsweep; } || run ...

Same change for E11e. E11f already writes one directory for both modes, so its guard is
already correct.
